# Procure Sherpa v2.4 — Completion Ledger

Audited 2026-11-01. **Every row below was read out of the code in `src/` and out of the live output of the gate tools named in "How to re-verify"** — not out of `IMPROVEMENT_ROADMAP.md`, not out of `docs/v2.4-delivery-report.md`, not out of `README.md`. Where a row rests on a test, the test is named and the reason it could fail is stated. Where a row rests on content that no test touches, the row says so and drops to YELLOW. Counts were recomputed from the built artifact (`ProcureSherpa-v2.0.html`, build stamp `47ac14587fdd`, drift-checked clean against the 177 fragments in `src/manifest.txt`), not quoted from documentation.

## Legend

- **GREEN** — the requirement is implemented AND an actual assertion exercises it. The row names the implementing file and line, and names the gate or test that would fail if the behaviour broke. If nothing asserts it, the row is not GREEN no matter how complete the code looks.
- **YELLOW** — present but partial, scaffolding only, unverified, or verified only by an assertion that could not fail. The row says which.
- **RED** — absent.

## How to re-verify

| Evidence type | Command |
| --- | --- |
| Every gate's summary (routes, calculator assertions, layout, integrity, a11y, perf, i18n) | `npm run qa` prints all of them (slow); a single number is cheaper: `node tools/smoke.mjs`, `node tools/test_integrity.mjs`, `node tools/perf_check.mjs`, `node tools/a11y_audit.mjs`, `node tools/test_calcs.mjs`, `node tools/test_calc_values.mjs` |
| Content registries actually registered, item by item | `node tools/inventory.mjs` (and `node tools/dump_index.mjs` for titles) |
| Relationship / link integrity | `node tools/check_rels.mjs` |
| One registry or field read out of the artifact | `node -e` or a jsdom probe against `ProcureSherpa-v2.0.html` (see `tools/test_interactive.mjs` for the loading boilerplate) |
| A route's rendered size and runtime errors | `node tools/smoke.mjs` (per-route chars; its "empty" threshold is `< 60` chars, `tools/smoke.mjs:70`) |
| Calculator value correctness | `node tools/test_calc_values.mjs` (hand-computed fixtures) and `node tools/test_calcs.mjs` (envelope/finite/required-field) |
| Utility/sanitiser behaviour on the shipped code | `node tools/test_unit.mjs` |
| Integrity gates G1–G20 | `node tools/test_integrity.mjs` |
| Deploy-only counts (NOT in `npm run qa`) | `node tools/verify_deploy.mjs` |
| Node version gate | `export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"; nvm use 22` first — the repo refuses Node 20 |
